# 机器人群发

桌面入口：后台管理 → 消息工具 → 机器人群发，地址 `/auth/settings/robot-messages`。左侧页签“发送历史”，右侧“权限管理”。本功能通过统一富文本编辑区主动发送文字和图片通知，不接收或展示钉钉聊天回复。

## 使用

1. 后台管理员可以直接发送，也可在“权限管理”按部门、含下级部门或人员授权。具体人员可排除、恢复，排除优先；后台管理员固有权限不受此处排除规则影响。这里的授权仅授予机器人发送能力，不授予后台管理能力。
2. “发送历史”以表格显示每次发送的时间、发送人、群聊/人员、消息内容和结果。右上角“发送消息”相当于新增：打开居中弹窗，在上方选择多个群聊和人员，可以混选，合计最多 100 个目标。人员来自当前已启用部门中的在职、启用钉钉员工，可按姓名、员工 ID、拼音和首字母搜索。员工 ID 始终作为字符串处理，保留前导零。
3. 在弹窗下方使用与应用模板相同的富文本输入区：直接输入文字、Ctrl+V 粘贴截图/图片，或点击“添加图片”。支持纯文字、纯图片和图文混排，无需选择消息类型；点击图片可预览原图。图片限 PNG/JPG/GIF/WebP，每条最多 6 张，图片原始字节合计不超过 8 MB，单张不超过 2000 万像素。点击“发送”。受理后关闭弹窗并回到最新历史记录；点击记录或“详情”打开详情抽屉，查看完整图文和每个接收对象的结果；历史表格显示文字摘要和图片缩略图，旧文字记录继续兼容。内容包含中文时按 UTF-8 计算，序列化后的消息参数不能超过 15,000 字节。后台异步逐个发送，页面自动刷新正在处理的记录。
4. 历史采用两行表头，列名下方按发送日期（北京时间）、发送人、发送对象（群名或人员姓名）、消息内容、发送结果组合筛选，每页 20 条；接收对象选择列表展示群聊的成功受理次数。管理员能看全部记录，普通获授权人员仅能看自己的发送记录。历史从本功能开始记录，不虚构导入早期探测消息。
5. 管理员通过“登记群聊”填写群名和 `openConversationId`。必须先将对应机器人加入目标群；无法凭名称搜索任意钉钉群。迁移会登记已验证的“渠道销售部”，仅在当前机器人为 `dingnkk0yssd8zyuwcif` 时显示。如何取得群标识见 [钉钉接入指南](../../docs/DINGTALK_GROUP_MESSAGING.md)。

表单和权限有未保存保护。提交期间禁止重复发送、切换页签及离开；提交结果不明确时，列表显示“查看待确认发送”，打开原发送弹窗后可“核对并继续本次发送”，始终沿用原请求编号。待确认请求（含图片）保存在浏览器 IndexedDB 中，按当前页签、有效用户和实际操作者隔离，刷新后继续核对原请求，确认服务端已保存后清除。页签标识保存在 sessionStorage 中；兼容旧版 sessionStorage 里的文字请求。未提交的编辑草稿不持久化；浏览器存储不可用时保留当前草稿且不提交，避免无法恢复的不确定请求。

## 浏览器 API

除带随机访问令牌的图片读取端点外，全部端点使用现有 Auth 登录会话和同源写入保护，经过服务端独立权限检查。内部应用请使用独立的 [机器人通知内部接口](../../docs/ROBOT_NOTIFICATIONS_INTERNAL_API.md)，不要把浏览器登录接口用于系统任务，也不能导入 Auth 私有代码或直连 Auth 数据库。

| 方法及路径（统一前缀 `/api/org/robot-messages`） | 行为 |
| --- | --- |
| `GET /capabilities` | `canSend`、`canManage`、`configured`、`maxTargets`、`maxImages`、`maxImageBytes` |
| `GET /groups` | 当前机器人的启用群，含 `id`、`name`、`sentCount`（本人可见的钉钉受理次数）、`lastSentAt` |
| `POST /groups` | 管理员登记群；`name`、`openConversationId`；重复群返回 409 |
| `GET /people?keyword=zs` | 启用员工，前 100 人及总数；支持目录搜索 |
| `GET /permissions` | 管理员读取规则、`revision`、`orgRevision`、实际生效人员 |
| `PUT /permissions` | 管理员保存 `rules`、`revision`、`orgRevision`；版本过期返回 409，前端保留草稿 |
| `POST /send` | 创建发送批次，首次返回 202；相同请求和相同内容重复提交返回已有结果 |
| `GET /public-images/{imageId}/{accessToken}` | 提供已校验的图片；无需登录，必须持有该图片的完整随机链接；错误令牌或文件缺失返回 404 |
| `GET /requests/{requestId}` | 获取调用者可见的单次请求和逐个收件结果 |
| `GET /history?page=1&groupId=1` | 每页 20 条；列筛选参数为 `sentDate`（YYYY-MM-DD，北京时间）、`sender`、`target`、`content`、`status`，条件按 AND 组合，先筛选后分页；兼容原 `groupId`、`keyword` |

发送请求示例（`groupIds` 是登记群的数据库 ID）：

```json
{
  "requestId": "c48f4157-85cf-4c64-b7d3-56c1f5a08345",
  "contentHtml": "<p>会议时间调整为下午三点。</p>",
  "groupIds": [1],
  "userIds": ["01333608525827896521"]
}
```

`contentHtml` 使用受限 HTML，图片使用 `<img src="data:image/png;base64,...">` 等内联数据；服务端校验真实图片格式、大小、尺寸，清理事件/样式/脚本，不下载任意外部图片。总请求体上限 12 MB。新页面统一转换为钉钉 `sampleMarkdown`，每个目标只发送一条图文；兼容已有客户端的 `content` 纯文字请求（仍用 `sampleText`）。历史返回 `content` 摘要、`contentHtml`、`messageType` 和 `images`。同一次重试须保留原始 HTML，不要重新格式化或改变图片数据。

`requestId` 必须为本次用户发送动作生成的 UUID。网络重试继续使用同一编号和相同内容；更改内容或收件对象时不能复用编号。冲突返回 409。批次保存有效身份和实际操作者用于代理审计；按有效身份校验权限，不继承代理操作者的管理员权限。

## 内部应用通知

手动富文本、内部兼容内容字段及结构化卡片按钮中的 HTTP(S) 网页链接转换为钉钉 AppLink：手机 `target=fullScreen`，电脑 `targetDesktop=workbench`，指定使用钉钉工作台。支持直接粘贴网址及富文本超链接，图片地址不转换；历史预览保留原地址。要求 Android/iOS ≥6.5.45、macOS/Windows ≥7.0.40；旧消息不追溯修改，内置打开不等于免登。详见 [网页链接打开约定](../../docs/ROBOT_NOTIFICATIONS_INTERNAL_API.md#网页链接在钉钉内打开)。

内部应用通过自身已登记且启用的服务凭据调用 `POST /api/internal/robot-messages/send`、`requests/get` 和 `groups/query`。支持没有人员登录的系统任务，与人工发送共用图文转换、图片存储、持久化幂等和逐目标发送队列；服务身份决定来源，不接收客户端伪造的人员身份。

历史中的应用通知显示应用名称，详情显示来源 App ID 和业务编号；管理员可看全部，普通人工发送者看不到其他应用的记录。内部查询仅允许原应用的原服务读取。人工页面的人员发送授权不约束应用系统通知，业务权限和收件范围由调用应用后端校验；队列执行前重新验证服务归属、启用状态及收件对象。

内部请求使用 `messageRequestId` 作为持久通知 UUID，`businessKey` 用于业务关联。HTTP 的 `requestId` / `X-Request-Id` 只是链路追踪编号。兼容字段 `content` 和 `contentHtml` 继续统一转为 Markdown；内部新增 `message` 对象支持原生文字、Markdown、图片、链接、操作卡片（竖向 1–5 按钮/横向双按钮）、文件、语音和视频，人工发送页面保持图文编辑。新增素材上传、素材查询和能力查询，素材按应用/服务/机器人隔离，发送历史保留内容摘要。原生 `text` 正文保持调用方语法，其中链接需用 SDK `client.link()` 显式转换；完整参数、错误处理、共享 Python 客户端及接入顺序见 [内部接口文档](../../docs/ROBOT_NOTIFICATIONS_INTERNAL_API.md)。

## 状态和防重复

| 状态 | 含义 |
| --- | --- |
| `pending` | 已保存，等待队列执行 |
| `sending` | 已认领，正在尝试发送 |
| `accepted` | 钉钉返回有效回执，已受理；不表示已读 |
| `failed` | 明确拒绝、权限/对象失效、入队失败或排队过期 |
| `unknown` | 超时、连接中断或无明确回执，需要人工核实 |
| `partial` | 批次汇总状态：部分成功、部分明确失败 |

一次只向一个群或一个员工调用钉钉接口，所以能独立记录和展示结果。发送 POST 无自动重试。持久化的条件更新 `pending → sending` 防止重复队列任务重复发送。发送之前重新核验有效发送人、代理操作者、发送权限和收件对象。权限撤销、离职或账号禁用会阻止尚未发送的对象；系统白名单沿用既有账号状态豁免。

入队失败时，尚未认领的记录被原子标记失败，迟到任务也不会继续发送。超过一小时仍未处理的目标停止发送；已认领超过三分钟未返回的目标在读取历史时转为“结果待核实”。后台任务重新执行时也处理过期记录。消息可能已被钉钉接收但回执丢失，系统不承诺外部接口严格 exactly-once；未知结果必须核实，不能自动重发。
